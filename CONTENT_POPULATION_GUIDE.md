# Content population guide

This guide begins after the foundation reset. It prevents the visual system
from becoming a container for unstructured material.

## Record entry checklist

Before a project receives a layout, confirm:

- Canonical title and slug
- Start and end date
- Ongoing status
- Record kind
- Parent record, if any
- Industry, Independent, and/or Academic context
- Relevant practice tags
- Verified role or responsibility
- Template family
- Credits and permission status
- Asset rights, dimensions, captions, and alt-text intent

Do not write a project summary until those facts are stable.

## Template selection

Choose the template by asking what an employer needs to understand.

- Use Registry Dossier when contribution, responsibility, coordination, or
  outcome is the main evidence.
- Use Visual Folio when sequencing images is the main evidence.
- Use System / Process Study when decisions, iterations, technical development,
  or fabrication are the main evidence.
- Use a Collection container only for a sustained parent body, experience, or
  education record.

Context does not select the template. An Academic project can still be a strong
Visual Folio; an Independent project can still be a rigorous System Study.

## Recommended first three populated records

Populate one record from each family before scaling:

1. A professional or hybrid Registry Dossier.
2. A fashion/image-led Visual Folio.
3. A product/3D-led System Study.

This exposes weaknesses in the shared components early and prevents every
project from becoming a custom page.

## Writing hierarchy

### Thirty-second layer

Keep visible near the project title:

- What it was
- When it happened
- In what context
- Joseph’s role
- Which practices it proves
- One factual outcome or deliverable, if verified

### Two-minute layer

Explain:

- The brief or opportunity
- Scope and constraints
- Joseph’s specific contribution
- Collaborators and boundaries
- The resulting work

### Deep layer

Use only when evidence exists:

- Research
- Iteration
- Technical details
- Production decisions
- Process documentation
- Credits
- Reflection

Do not inflate small work into a long case study. A concise, complete folio is
stronger than a padded dossier.

## Parent bodies

Volume, MT570, PUPIL / Sean Leon, and Toronto Metropolitan
University should act as navigable lineages.

The parent presents:

- Period and context
- A concise high-level role
- Child records ordered chronologically
- A duration band
- Shared practices

Each child remains directly addressable. The parent should never hide a strong
individual project behind several layers of navigation.

## Asset preparation

For every image:

- Preserve a high-resolution archival original outside the deployable site.
- Export a colour-managed web master.
- Create responsive widths only when the final layout is known.
- Write a factual caption before writing alt text.
- Decide whether the image is informative or decorative.
- Record creator, owner, permission, and credit.

For video:

- Supply a poster image.
- Avoid autoplay.
- Include captions or a transcript when speech or sound carries information.
- Provide a reduced-data alternative.

## Quality gate per record

A record may move from `draft` to `published` only when:

- All copy is verified.
- The contribution is unambiguous.
- Credits are complete.
- Every media asset has a defined crop and responsive behaviour.
- Keyboard, screen-reader, reduced-motion, and mobile states are checked.
- No module is empty.
- Its practice and context links return meaningful collections.
- It strengthens rather than duplicates the first-view understanding of the
  overall practice.

## Editorial restraint

- Do not use every available module.
- Do not repeat the same opening paragraph in the parent and child.
- Do not call every task “creative direction.”
- Do not claim outcomes that cannot be demonstrated.
- Do not use aesthetic texture to disguise weak hierarchy.
- Do not publish work simply because a project name already exists.

The registry is allowed to stay sparse. The purpose of the system is to make
strong work legible, not to maximize volume.
